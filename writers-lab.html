Build practical skills

What you can practice

Work through the decisions technical writers make every day—from word choice to developer-facing reference content.

01 / STYLE

Style guide compliance

Apply industry guidance, including the Microsoft Writing Style Guide. Remove passive voice, directional references such as “above” and “below,” and ambiguous pronouns.

02 / STRUCTURE

Information structure

Turn raw engineering notes, code comments, and complex requirements into clear, task-based procedures.

03 / DEVELOPER DOCS

Developer documentation

Write useful descriptions for API endpoints, parameters, and error responses.

04 / AUDIENCE

Audience analysis

Adapt tone, technical depth, and vocabulary for readers from new developers to IT administrators.
